## 先确认你要测的是哪一台

DMIT 洛杉矶机房对外提供三个测试节点，分别对应三条产品线。别随便 ping 一个就下结论，测错节点等于白测。

| Tier 1（T1） | 国际 BGP，不针对中国大陆优化 | `174.136.204.135` | `lg.dmit.sh` |

`lg.dmit.sh` 是官方 Looking Glass，页面上可以切换机房节点，然后跑 Ping、Traceroute、MTR 和下载测速。它是从服务器那侧往外测的，这点后面会说到为什么重要。

三条线路的具体走法：

- **Pro**：IPv4 去程电信走 CN2 GIA（AS4809）、联通直连 AS4837、移动走香港移动 AS58453；回程三网统一走 AS4809。IPv6 则走 AS9929 与 CMIN2。
- **EB**：电信在 AS9929（联通精品网）和 AS58807（CMIN2）之间做负载，联通主要走 AS9929，移动主要走 CMIN2。
- **T1**：普通国际路由，不针对中国方向做优化，胜在便宜、流量大。

## 测速要分两段：去程和回程

很多人只 ping 一下就收工，这只能看到“去程”——你的电脑到洛杉矶这段路。数据回程走什么线路，ping 是看不出来的。

完整流程大概是这四步：

1. **先在本机 ping 测试 IP。** Windows 下 `ping 154.17.30.96 -t`，macOS 和 Linux 直接 `ping 154.17.30.96`。看两个数：平均延迟和丢包率。
2. **打开 Looking Glass 测回程。** 选好节点，命令选 Traceroute，目标填你自己的公网 IP（不知道就去 ip.sb 之类的页面查一下），运行后看数据包是从哪些骨干网绕回来的。
3. **有丢包再跑 MTR。** MTR 相当于 ping 和 traceroute 合体，能看到具体是哪一跳开始丢包，是本地运营商出口的问题还是境外段的问题，一目了然。
4. **最后看带宽。** LG 页面上有下载测速，也能顺便观察一下速度是不是稳定。

看路由结果时，认几个 AS 号就够了：

- `AS4809`：电信 CN2 GIA，回国质量最好的一档
- `AS9929`：联通精品网（CUG）
- `AS58807` / `AS9808`：移动 CMIN2 及移动骨干
- `AS4134` / `AS163`：电信普通骨干，延迟明显更高
- `AS4837`：联通普通线路，晚高峰容易抖

> 一句话：traceroute 里出现 AS4809、AS9929、AS58807 算好路，只有 AS4134、AS4837 说明你测的那台大概率不是优化线路，或者走的是兜底路由。

## 延迟多少算正常

下面的数字来自第三方测评者的实测记录，不是官方承诺值。你的结果会受本地宽带、所在城市和测试时段影响，参考区间比绝对数字更有意义。

洛杉矶节点从中国大陆访问，**150–170ms 属于正常范围**。这个区间在 Pro 和 EB 上比较常见。有几组可以对照的实测数据：

- 一台 EB 系列（EPYC 9654，1 核 1G）的测评中，三网平均延迟为电信 163ms、联通 160ms、移动 156ms；
- 一台 T1.STARTER（EPYC 9005）的测评中，电信 156ms、联通 160ms、移动 158ms；
- 另一份 T1.TINY（1 核 1G）的测评结果明显更差，全国平均 208ms，其中电信 180ms、联通 198ms、移动 255ms，港澳台地区反而是最低的 154ms。

同样标着 T1，两次结果差出 50ms，说明单看一张测评图的平均值容易误判。**更值得关注的是晚高峰**——晚上八九点再测一次，如果延迟只上浮十几毫秒、丢包还在 1% 以内，这条路才算过关。丢包超过 5% 就要警惕了。

还有个小坑：部分移动线路对 ICMP 做了屏蔽，监控面板上会显示移动方向丢包，但实际用起来没影响。这种时候别只看 ICMP，搭配 TCP 层的测试或者实际下载更靠谱。

## 测完结果怎么对到选型上

测速数据的用途就一件事：判断你该买哪条线。

**三网延迟都在 150–170ms、丢包接近 0**：说明你这条宽带走 DMIT 任何一条优化线路都不差。这种时候按预算和流量定就行，EB 在同价位给的流量通常更大。

**电信明显优于联通、移动**：Pro 是更稳的选择，回程 CN2 GIA 对电信用户最友好。反过来，如果你是联通或移动宽带，EB 的 AS9929 + CMIN2 组合性价比更高，不必为 Pro 的溢价买单。

**只做备份、下载、面向海外的业务**：T1 就行。延迟不是它的卖点，低单价和大流量才是，年付 36.9 美元的入门款在同类产品里很难找到对手。

**测出来延迟常年 200ms 以上、丢包还高**：先别急着怪商家，用 traceroute 看看是不是自己本地运营商出口的问题。换个时段、换个网络再测一次，结论会不一样。

## 两个容易被误判的测速场景

**超量限速之后测速。** 如果你已经跑完了当月流量，无论 Pro 还是 EB，带宽都会被压到 4Mbps 或 8Mbps，晚上测出来几百 KB/s 是正常的，不是线路坏了。想验证线路质量，先看当月流量还剩多少。

**换过 IP 之后测速。** DMIT 的 Pro 和 EB 系列支持自助换 IP：实例开通满 7 天、距上次换 IP 超过 15 天、ICMP 和所有 TCP 端口都被封、剩余服务期不少于 7 天，这四条同时满足可以免费换一次。T1 系列不适用免费规则，只能付费更换，每次 5 美元，间隔 3 天。换完 IP 后原先的测速结论就不作数了，路由和延迟都得重测一遍。

## 几个常被问到的测速问题

**Looking Glass 页面打不开？** 先确认网络本身能访问国际站点。LG 页面是网页端工具，国内直连访问偶尔不稳，换个网络环境再试。

**能不能直接把测速文件链接拿去下载？** 不建议。部分节点限制了直链下载，反复拉取还可能触发限制。要看带宽就在 LG 页面上点测速按钮，测完就停。

**IPv6 需不需要单独测？** 需要，如果你的业务真的会走 IPv6。DMIT 洛杉矶的 IPv4 和 IPv6 路由策略不完全一样，Pro 的 IPv6 走的是 9929 与 CMIN2，跟 IPv4 的 CN2 GIA 是两套东西。判断方法和 IPv4 一样：ping 对应地址，再用 traceroute 看回程。

**为什么测评里移动方向总显示丢包？** 如前文所说，部分移动线路对 ICMP 做了限制，监控平台会误报，实际使用不受影响。以 TCP 层测试和实际下载速度为准。
